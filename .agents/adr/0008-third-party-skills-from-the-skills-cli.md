# 0008: Other people's skills come from the skills CLI, pinned in the repo

Status: accepted, 2026-11-13. Supersedes ADR 0006.

**Context.** Skill authors now publish one install command, `npx skills add <owner>/<repo> --skill <name>`, for every agent. ADR 0006 kept Matt Pocock's skills in a clone linked with Stow, which suited one source but needed a clone and a bucket entry for each new one, such as hunk's or herdr's single skill. The skills CLI installs a copy into `~/.agents/skills/<name>` and, for Claude Code, a link to it from `~/.claude/skills`: the two folders this repo already serves (ADR 0003). Its global record keeps the source, path and a folder hash, plus the ref only when one is given; it keeps no commit, cannot be replayed on another machine, and `skills update` replaces a skill with its latest version without showing what changed. It silently replaces a same-named entry in those folders, and it sends usage data unless `DISABLE_TELEMETRY` or `DO_NOT_TRACK` is set.

**Decision.** This repo's own skills stay linked with Stow, so an edit reaches every agent at once. Every other skill, Matt's included, is installed with the skills CLI, pinned with Node in the repo's `mise.toml`, which also turns its telemetry off. `scripts/skill-sources.sh` lists each source with a pinned tag or full commit and what to take from it: a folder of skills, one skill's folder, or a skill name. `scripts/install-skills.sh` installs the list for Claude Code and the agents that read `~/.agents/skills` (`-g -a claude-code -a codex`), skips what is already at its pin, removes what the list no longer names, and refuses a name that clashes with this repo's skills or another listed one. `scripts/update-skills.sh` shows, per source, the commits since the pin that touched the listed skills, moves the pin only after confirmation, then installs; committing the list pins every machine.

**Alternatives rejected.** Stow links for every source (ADR 0006): a clone and a bucket entry per source, even for one skill. The CLI's own `update`: no review and no recorded commit, so machines drift. Always the latest version: an upstream change reaches agents before anyone reads it. `npx skills`: downloads the newest CLI on every run.

**Consequences.** The skills CLI runs only through the scripts: run without `-g` in this repo, it would install into the repo's `.agents/skills/`, which other agents load as project skills. A third-party skill is a copy that the next install replaces; to change one, copy it into `skills/dotfiles/` under a new name. The doctor runs `install-skills.sh --check` and `check-skills.sh`, which fails when a third-party skill takes the name of one of this repo's. Each machine runs `mise trust` on the repo's `mise.toml` once; `scripts/setup.sh` does it.
