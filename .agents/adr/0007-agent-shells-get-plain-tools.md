# 0007: Aliases only in human shells, so agents get commands as documented

Status: accepted, 2026-10-23.

**Context.** The interactive layer gives classic commands new behavior under their own names: bat as `cat`, eza as `ls`, delta as `diff`, extra flags on `rg`, prompts on `rm`, `cp` and `mv`. AI agents (Cursor, Claude Code and others) run their commands through the same interactive zsh, with no one to answer a prompt or read a pager. Seen in practice: `rm` with no terminal printed its prompt, read end of input as "no" and kept the file; `cp -i` refused an agent's restore; the `rg` alias's `--line-number` corrupted a path piped from `rg -o`; `cat -v` failed because bat rejects `-v`. zoxide records every folder a shell visits, and the Cursor sandbox cannot write its database.

**Decision.** Aliases are created only in human shells (a terminal, a herdr pane), never in agent shells, and no other program takes a command's name on `PATH` (bat never becomes `cat`). `.zshrc` decides once whether a shell is an agent shell: stdin is not a terminal, or `AI_AGENT` is set and not `0`, `false`, `no` or `off` (the emerging cross-tool convention), or one of the vendor markers listed there is set. The legacy `AGENT` is ignored: its readers disagree on its meaning, and every agent known to set it also sets a vendor marker. The alias definitions sit behind that check, and zinit's own aliases are off, so an agent shell has only zsh's built-in `run-help` and `which-command`. Agent shells also skip zoxide, thefuck, web-search and fzf-tab's Enter-runs-the-line. `cd` is zsh's builtin in every shell; zoxide's `z` and `zi` exist only in human shells. `PATH`, mise, direnv, completions and the prompt are the same for both.

**Alternatives rejected.** Wrapper programs in `~/.local/bin`: scripts and agents would get them too. No replacements: loses the conveniences people chose them for. Replacements everywhere: the failures above. Creating the aliases, then removing them in agent shells, all or only those that shadow a command: aliases have no use there, and a removal step would quietly hide an alias a plugin adds instead of the test catching it.

**Consequences.** The markers are hints anything can set, so they only switch conveniences off, never anything security-related. A person gets plain tools in a shell whose stdin is not a terminal, and in Claude Code's IDE terminal, which sets `CLAUDECODE`. An agent with no marker is caught only if its shell has no terminal. A herdr server started from inside an agent can pass that agent's markers to every pane (herdr issue #4631); if human panes lose their aliases, restart the server from a WezTerm tab. Agent navigation never reaches zoxide's history, so `z` ranks only the folders people visit. New agent markers go in the list in `.zshrc`, and new aliases inside its agent-shell check. `scripts/test/test-keybindings.zsh` checks the detection, and fails if an agent shell has any alias beyond zsh's two.
